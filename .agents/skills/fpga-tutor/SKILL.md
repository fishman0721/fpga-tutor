# FPGA 助学助手（fpga-tutor）

本技能把一个 FPGA 工程变成一份**单文件、可本地双击打开**的交互式学习页面
（`study/fpga_study.html`），并围绕该页面与用户持续讨论、迭代。

## 核心约定

1. **只精读，不灌库**：FPGA 工程可能很大。用 glob 扫描目录结构、用 grep 定位关键内容，
   只完整读取 RTL / testbench / 约束文件（`.v` `.sv` `.vhd` `.xdc` `.sdc`）。
   IP 核、仿真产物、波形、编译中间目录（`ip/`、`sim/`、`runs/`、`.cache/`、`project_*`）只列摘要，不读内容。
2. **产物固定位置**：学习页面写入**被测工程根目录下新建的 `study/` 文件夹**（如 `<工程根>/study/fpga_study.html`），讨论笔记写入同目录 `study/notes.md`。不要把产物放在会话工作区。
3. **页面规范**：单文件 HTML，CSS/JS 全部内嵌，**零外部依赖、零 CDN**，保证 `file://` 双击即开、离线可用。
4. **基于模板生成**：以 `templates/study-page-template.html` 为骨架，替换其中的占位符并填充
   `TASKS` / `QUIZ` / `GLOSSARY` 三个数据数组。模板内保留了完整的样式与交互逻辑，不要重写它们。
5. **迭代式更新**：用户每次提出修改意见后，用 edit 工具增量修改 `study/fpga_study.html`，
   不要整页重生成（除非页面结构变化太大）。

## 标准流程

### 第一步：扫描工程
- 用 glob 列出全部源文件，识别：顶层模块、RTL、testbench、约束文件、IP/仿真等大目录。
- 阅读顶层模块与工程文档（README、`.xpr`/`.qsf` 工程文件可 grep 关键信息，不必全读）。
- 给用户一份 3~5 行的工程概览（语言、器件/开发板、主要功能、模块数量），再生成页面。

### 第二步：生成学习页面
按模板生成 `study/fpga_study.html`，至少包含：

| 章节 | 内容要求 |
|---|---|
| 工程概览 | 一句话功能说明 + 器件/开发板 + 目录结构树 |
| 模块层级 | 采用**教程式模块框图**（参考黑金《36_sobel》doc 目录 sobel.vsdx 风格）：各模块画成独立方块、横向排成数据流；端口画在方块边缘（输入在左、输出在右）；信号用**带名称的箭头连线**（流向 + 名字标注）；被测试模块用高亮边框；独立模块/输出文件用虚线框。框图用内嵌 SVG 绘制，零外部依赖 |
| 端口与信号 | 顶层端口表（方向/位宽/作用）+ 各模块关键内部信号 |
| 关键代码解读 | 挑 3~6 段真正重要的代码（状态机、计数器、跨时钟域、接口时序等），逐段讲解 |
| 学习任务清单 | 5~10 个从易到难的任务（改代码、画时序、写 testbench、做仿真等），放进 `TASKS` 数组 |
| 小测验 | 5~8 道选择题，放进 `QUIZ` 数组，答案与解析要具体 |
| 术语表 | 本工程涉及的概念（CDC、亚稳态、时序约束等），放进 `GLOSSARY` 数组 |
| 我的笔记 | 页面自带，用户输入自动保存在浏览器本地 |

### 第三步：交付与讨论
- 收尾消息中把 `study/fpga_study.html` 写成行内代码，方便点击打开。
- 主动给出"今天的三个学习重点"与"建议下一步"。
- 用户提出任何问题，先回答，再按需更新页面（任务、测验、讲解内容都可加）。

## 边界与注意

- 只讲**用户的项目**，不虚构功能；拿不准的代码行为要标注"需结合仿真/文档确认"。
- 涉及修改工程源码的请求，生成页面之外的操作要先和用户确认。
- 页面里嵌入的代码片段保持精简（关键行即可），全文件照搬没有学习价值。
- 生成的页面是学习材料，不替代 Vivado/Quartus 仿真与综合验证。
